## kranneva.ru — этап 1 (шелл/шаблон), 25.09.2026

**Контекст:** Next.js 16 (App Router, статический экспорт через `next build` → `out/`), почти весь сайт — Server Components. `grep -rl "'use client'" app` не нашёл ни одного компонента контентных страниц (только форма `KpForm.tsx`). Готового TOC/byline-компонента, в отличие от moskran-servis и manipmo, на сайте нет вовсе.

**Baseline (65 контентных страниц):** 2 FAIL, 63 WARN, 0 PASS. Топ: нет автора (65), H2 без id (63), сущность не названа (63), нет TOC (51), нет FAQ (49), первое предложение не тезис (53), intro <N слов (6), длинное первое предложение (23), длина description (8).

**Сделано:** `scripts/geo2026-postbuild.mjs`, подключён в `package.json` → `postbuild` (последним шагом после `prune-export`/`emit-redirects`/`emit-sitemap`). Проходит по `out/**/*.html`, добавляет `id` на каждый `<h2>` внутри `<main>` (та же транслитерация-слаг, что на kran365/moskran-servis/manipmo). После патча: 89 файлов проверено (включая redirect-заглушки и файл верификации Яндекса — не контент), 63 изменено; «H2 без id» и «нет оглавления» полностью пропали из топ-10 предупреждений чекера.

**ПОПЫТКА, которая НЕ пошла в прод — записываю честно:**
Изначально скрипт также вставлял новый `<nav class="g26-toc">…</nav>` (с собственным инлайновым `<style>`, так как готового TOC-компонента на сайте нет) перед первым H2, при ≥3 заголовках на странице. Гипотеза была: раз на контентных страницах нет `'use client'`-компонентов, вставка нового узла не столкнётся с клиентской гидратацией — в отличие от manipmo.ru (Vue/Nuxt), где ровно эта же операция уже один раз дала регрессию.
**Гипотеза оказалась неверной.** Живая проверка в браузере (`http://localhost:8792/obekty/krovlya-deystvuyushchego-zdaniya/`) с вставленным TOC показала в консоли:
```
Uncaught ... Minified React error #418
```
— это React-эквивалент Vue-предупреждения "Hydration completed but contains mismatches": Next.js 16 гидратирует **всё** дерево статического экспорта на клиенте, независимо от того, есть ли в нём интерактивные острова. Вставка узла, которого не было в исходном SSR-выводе, ломает эту гидратацию так же, как на Nuxt.
**Откатила TOC-вставку** (осталась только правка комментария в самом `geo2026-postbuild.mjs` с объяснением). Оставлена только правка `id`-атрибута на уже существующих узлах `<h2>` — это НЕ новый узел, и живая проверка с ней консоль чистая (`No console logs`).

**Правильное решение на будущее** (не сделано в этом проходе): написать TOC не постройкой снаружи, а как часть самого React-дерева — т.е. собирать список H2 на сервере (в `page.tsx`/layout, до рендера) и рендерить `<nav>` как обычный Server Component рядом с `<main>`. Тогда узел будет частью исходного SSR-вывода, который клиент ожидает при гидратации, и проблема просто не возникнет — примерно то же самое решение, что записано как рекомендация для manipmo.ru (`tocItems` синхронно в `setup()`), только применительно к другому фреймворку.

**Живая проверка:** `/obekty/krovlya-deystvuyushchego-zdaniya/` — 3/3 H2 с id (включая уже существующий `sources-heading` от компонента `Sources.tsx` — скрипт корректно не тронул готовый id), консоль чистая на десктопе и при перезагрузке в мобильном viewport (375×812), `scrollWidth == clientWidth == 375` — без горизонтального скролла.
